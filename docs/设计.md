# 设计

> 内部设计:存储作用域、模块划分、可编辑视图与回写机制、踩过的坑。
> 用户上手请看 [使用指南](使用指南.md);元素级能力看 [能力矩阵](能力矩阵.md)。

## 一、存储作用域:只用项目存储

| 项 | 决定 |
| --- | --- |
| 作用域 | **项目存储**(不写壳子存储) |
| 位置 | `<项目根>/.dshm/docx/<文件名>-<sha8>[-样式][-编辑]/` |
| 规则来源 | `存储布局.md` §3(包名去 `dshm-`、去分类前缀 `tools-`、`-` 换目录 → `docx`)+ §4(项目存储) |
| 项目根怎么来 | 参数 `project`;省略时反推会话工作区;**推不出来就报错**,不退回进程工作目录(§4 规则 3) |

产物是**可再生缓存**:跟"这份文档"绑死,项目搬走/备份时一起走;不带跨项目状态,所以不设壳子存储。

## 二、产物布局

```
<项目根>/.dshm/docx/<文件名清洗>-<源sha256 前8位>[-样式][-编辑]/
├─ index.md        大纲 / 统计 / 资源清单 / 不可得 / 怎么读
├─ content.md      全文(便于 grep)
├─ chapters/       每章 ≤800 行(一次 read 能吃完)
├─ media/          图片附件
├─ styles.md       仅 styles:true —— 样式类表
├─ content.xml     仅 edit:true —— 可编辑视图
├─ raw/原文档.docx 仅 edit:true —— 回写母版
└─ manifest.json   源指纹 + 选项 + 转换器版本(缓存判断)
```

目录名带源文件 sha256 前 8 位:文件一改就是新目录,旧产物不会冒充新的。
后缀区分版本(`-样式` / `-编辑` / `-样式编辑`),**多版本并存互不覆盖**;缓存键含选项与版本号。

## 三、两条铁律

1. **解析层不认识输出格式**:`word/*` 只产块对象,`output/*` 只消费块对象,`edit/*` 只做"模型 ↔ xml ↔ 包"。
2. **绝不静默丢**:读不到就产 `{类型:'不可得', 原因, 原值}`,输出成 `〔不可得:…〕`。

## 四、模块划分

```
src/
├─ index.js            插件壳:注册 doc_convert + doc_build
├─ pipeline.js         编排:打开包 → 解析 → 渲染 → 落盘(可选序列化 + raw 拷贝)
├─ store.js / paths.js / workspace.js    产物目录、缓存、唯一拼路径处、工作区反推
├─ tools/{convert,build}.js              两个工具的 schema 与返回摘要
├─ ooxml/{zip,zip-write,xml,package,ns}.js   ZIP 读写 / XML(含回写序列化)/ OPC 包 / 命名空间
├─ word/
│  ├─ document.js      主文档遍历器(唯一知道有哪几种块)
│  ├─ context.js       转换上下文(样式/编号/公式/媒体/统计/锚)
│  ├─ styles.js        样式链求解(basedOn + docDefaults)→ 标题层级 / 有效字号色字体
│  ├─ numbering.js     编号推算(多级、重启、中文/罗马)
│  ├─ props.js         文档属性(core/app/custom)
│  ├─ fields.js        域收集器(状态机 + 18 类分类 + 清单 + 是否需重算)
│  ├─ sdt.js           内容控件(类型 / 选项 / 数据绑定)
│  ├─ drawing.js       图形定位 / 变换 / 裁剪
│  ├─ layout/{border,paragraph,character,table,index}.js   版式与尺寸
│  ├─ inline/{runs,run,format,special}.js   行内编排 / 单 run / 格式规则 / 特殊字符
│  └─ blocks/{paragraph,fragment,table,image,embed,section,footnote,comment,altchunk}.js
├─ math/               OMML → LaTeX(入口 + 分派 + 12 个结构类 + 降级)
├─ output/
│  ├─ markdown/{inline,table,block}.js     行内 / 表格 / 块 三层
│  └─ {chapters,indexer,manifest,media,stylemap}.js
└─ edit/
   ├─ units.js         人话 ↔ 原生值(缇/半磅/EMU/角度/千分比),整数比换算
   ├─ writer.js        对象模型 → content.xml
   └─ build.js         content.xml + raw → docx
```

加一类内容 = 在 `document.js` 挂一行 + 写一个 block 模块 + 在 `output/markdown/block.js` 加一个 case。

## 五、可编辑视图(`content.xml`)

标识方案(**已定**):**XML 子集,元素名 = OOXML 元素名;属性扁平化;值写人话**。

```xml
<w:p w:pStyle="heading 1" w:jc="center" w:ind-left="0.5in" w:spacing-line="1.5x"
     w:numId="2" w:ilvl="1" w:anchor="w:document/w:body[0]/w:p[7]">
  <w:r w:b="1" w:sz="14pt" w:color="#C00000" w:font="黑体">加粗红字</w:r>
  <w:r><w:drawing w:kind="anchor" w:src="word/media/image3.png" w:posH="margin@left"
                  w:width="76.5pt" w:wrap="square" w:anchor="…/w:drawing[0]"/></w:r>
</w:p>
```

三条约定:

| 约定 | 原因 |
| --- | --- |
| 元素名就是 OOXML 名 | 回写零转换:`<w:p>` → `createElement('w:p')`;不用写逆向猜测器 |
| 属性扁平化(白名单) | 人读、diff 都清爽;低频/不熟的属性不扁平,原样留子元素 |
| 值写人话 + 固定换算 | `0.5in`↔720 缇、`14pt`↔28 半磅、`1.5x`↔360 都是整数比,不累积误差 |
| 每块带 `w:anchor` | 回写按它找回 raw 原文;锚点用**同名兄弟序号**,不能用全部子节点序号 |
| 未建模段落 `w:readonly="1"` | 能读不能改;回写整段搬回,避免"半懂不懂"地重建 |

## 六、回写(`doc_build`)

**重建 + 未建模回填**:

1. `raw/` 的部件先全量继承(样式、编号、主题、媒体都以 raw 为准);
2. 主文档 `<w:body>`:普通段落 / 表格 / 图片 / **分节(页面设置)** 按 `content.xml` 重建;
3. 段落的 `pPr` **以 raw 为底**:只覆盖编辑视图写了的字段,其余(边框/底纹/制表位/框架/大纲级别)原样搬;
   **唯一例外是 `pPr/w:rPr`(段落标记格式)**:不建模也不继承 —— 照抄会让改过字号的段落保留旧行高;
4. `w:readonly="1"` 的块按锚点**原文搬回**;
5. 页眉页脚 / 注释 / 批注部件原样继承(第一版不重建);
6. rels:目标在 raw 里已有就复用,没有就**新增一条**(`rIdMiaoN`),超链接同理。

**默认视图**:`settings.xml` 的 `w:view`(打开时用哪种视图)默认**不动**(那是读者端设置);
调用方明确要求时传构造参数 `视图: 'print'` 才改 —— **论文/正式文档必须按页看,排版时就用这个**。
校验:`verify-full` 里两条断言各盯一面(默认不动 / 指定后生效)。

## 七、踩过的坑(都已在代码里修掉)

> **`pPr` / `rPr` / `tcPr` / `sectPr` 是 schema sequence —— 子元素顺序错了 Word 会直接忽略。**
> 最典型的症状:设了 `pageBreakBefore` 却不分页(`pageBreakBefore` 排在了 `jc` 后面)。
> 现在回写统一按 schema 顺序排一遍(`build.js` 的 `顺序表` + `排序拼接()`),raw 兜底搬来的元素也一起排。

> **`<w:body>` 不能漏。** 早先回写把正文子节点直接塞进 `<w:document>`,Word 判定无效 → 打开一片空白。
> 我们自己的解析器对此是宽容的(找不到 body 就拿根元素当容器),所以自测没暴露;现在有三条结构性断言盯着。

> **锚点序号口径必须与查找口径一致。** 早先锚点按"父节点全部子元素序号"算、回写按"同名兄弟序号"找,
> 结果整片 TOC 段落被搬到别处。现在两边都按**同名兄弟**序号。

> **只读块不能只搬里面的 drawing。** 图表/文本框的 `<w:drawing>` 直接放到 `body` 上是非法结构。
> 规则改成:**含未建模对象的段落整段只读**,回写搬整段。

> **回写要补命名空间。** 原文档根上不一定声明 `a:` / `pic:`,重建出来的图片解析不出 blip → 4 张图全丢。
> `build.js` 的 `包壳()` 现在会补齐必需前缀。

> **超链接/图片的关系要能新增。** 否则目标 rel 不存在时链接退化成纯文本;新增关系时按"目标去重",避免刷一堆重复。

> **扩展名检查要按魔数兜底。** 早期用 `/\.docx$/` 直接把 `.doc` 拒掉;现在改为 `import/office.js` 的 `判定输入()`:先嗅容器魔数(OLE / ZIP / RTF / PDF),再结合后缀决定"直接解析 / 规范化 / 拒绝"。**不信后缀** —— `.doc` 改名成 `.docx` 会被认出来,RTF 改名成 `.doc` 也会被明确拒绝,而不是让它落到"不是有效 ZIP"那种误导性报错。

> **规范化是有损的,必须在 `不可得` 里留痕。** 非 docx 输入经 LibreOffice 转出中间 `_source.docx` 后再解析,字体可能被替换、版式可能被重排。`pipeline.js` 会追加两条 `不可得`(来源说明 + 缺失字体),manifest 的 `规范化` 字段记原始格式/引擎/后端/中间文件。

> **改输出行为要 bump `version.js`。** 缓存键含版本号;不 bump 会命中旧产物,断言验的其实是老结果。

> **PDF 必须先分类,判据是文本操作符密度而不是图片数量。** `import/pdf.js` 的 `分类PDF()` 只解压内容流数 `Tj`/`TJ`:
> 每页 < 10 → 图片型(扫描件,拒绝并要求 OCR);有文本层且每页 ≥ 1 图 → 混合型;否则文本型。
> 早期版本按"图像数 ≥ 页数"判,把一份图文混排的产品手册(每页 2.67 张图但有完整文本层)误判成扫描件 —— **图片多不等于没有文本**。
> 文本型/混合型交给 PDF 解析器转 docx;图片型没有文本层,任何工具都只能靠 OCR,所以直接抛 `UNSUPPORTED`。

> **PDF 解析器并存,产物目录必须带解析器名。** 同一份 PDF 用不同解析器产出的 docx 完全不同,所以:
> `paths.js` 的 `产物目录名()` 支持 `解析器` 段(`<名>-<sha8>-<解析器>`),`manifest.js` 的 `可用()` 也比对解析器 ——
> 换解析器绝不命中旧缓存。两份产物并排存在,谁好谁坏一眼可查。
>
> 实测同一篇 35 页 arXiv 论文(LaTeX 双栏):
> - `pymupdf4llm`(默认):44.6s,**标题 40 个**、可分 2 章、英文空格完整、产物 0.4 MB;
> - `pdf2docx`:107.7s,标题 0 个、英文单词粘连(`Axis-AttentiveDocument`)、矢量图全栅格化,产物 **237.7 MB**。
>
> 差异根源:LaTeX 用 kerning 精确控制字距,**不写真实空格字符**;pdf2docx 逐字定位后重排时无法恢复空格,
> 而 pymupdf4llm 走 PyMuPDF 的文本层,空格与标题层级都在。所以默认用 pymupdf4llm。

> **Python 调用不能用管道收输出。** 沙箱下 `child_process` 的 `stdio: 'pipe'` 会 EPERM。`import/python.js` 一律 `stdio: 'ignore'`,
> 只看退出码,诊断由 Python 侧写进 `log.txt` 再读回来;转换用异步 `spawn`,否则几百页 PDF 会阻塞整个事件循环。

## 八、验收

- `test/fixtures-full.js`:一份"每类内容都有"的 docx(标题/各级列表/合并与嵌套表/图片(行内·浮动·VML·兼容内容·外链·EMF)/23 个公式结构/全部域/脚注尾注/批注(含回复)/修订/SDT 六种/文本框/图表/SmartArt/OLE/altChunk/书签/超链接/分节/页眉页脚/文档属性)。
- `test/verify-full.js`:**175 项断言**,覆盖每个块、每个片段种类、每类版式字段,以及可编辑 + 回写往返。
- `test/verify-import.js`:**15 项断言**,覆盖魔数判定(改名的 RTF / `.doc` 冒充 `.docx`)、`.doc` 端到端规范化、来源与 `不可得` 落痕、缓存命中。(需要 `@deepseek-ai/libreoffice-kit` 引擎。)
- `test/verify-pdf.js`:**7 项断言**,覆盖 PDF 分类判据、图片型必须拒绝、文本型端到端中文可读、manifest 记录分类。(端到端需要 `pdf2docx` 与一份样本。)
- `test/roundtrip.js`:任意真实文档的往返对比(正文逐行 + 统计)。实测 calibre 1.3 MB 演示文档:310 行逐字一致。
- 新增能力时:**夹具加内容 → 断言加一条 → 能力矩阵加一行**,三处齐步。
